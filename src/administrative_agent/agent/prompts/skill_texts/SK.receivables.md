skill_key: SK.receivables
title: 当期应收账款（按客户）
version: 2026-09-17.1
index: 用户要当期应收账款（某客户／各客户还欠多少、当前应收明细）时使用：按客户逐户给出订单累计、累计实际收款、累计平账抹零三列并相减得当期应收
policies: R4.balance.scope
tools: erp_calc, erp_query
when_not: 只要未结余额（要与 ERP 财务页对得上的数）——引导到 ERP 财务-资产管理页查看；只要实际收付款流水的明细或发生额——直接查答，不必走本流程；任何写入（建单、改单、考勤写入、收支写入——本流程全程只读）；上传 Excel 做对账核对（走对账流程）
native_tools:
---

1. 定期间：把「当期月」定为当前自然月（用户明确指定了某月作当期时以该月为当期月），到期月 = 当期月往前推 2 个月（例：当期 9 月 → 到期 7 月）；据此算出两个具体日期——到期月末（到期月最后一天，形如 2026-07-31）与当期月末（当期月最后一天，形如 2026-09-30）。两个日期没定完不进入取数。本流程全程只读，不写任何数据。
2. 取 A：调用 erp_calc，参数 entity=metal_orders、filter={"in_date": {"lte": "到期月末"}}（把「到期月末」替换成第 1 步算出的日期，如 {"in_date": {"lte": "2026-07-31"}}）、group_by=customer_id、measures=[{"field": "total_amount", "op": "sum"}]。该次调用只放这一个金额 measure，不得混入重量/数量（混入会让金额被按单位分桶）。记下每个客户桶的合计为 A_c，记下顶层 totals 给出的合计为「A 合计」。
3. 取 B：调用 erp_calc，参数 entity=ar_payments、filter={"pay_date": {"lte": "当期月末"}}、group_by=customer_id、measures=[{"field": "amount", "op": "sum"}]。记下每个客户桶的合计为 B_c，记下顶层 totals 给出的合计为「B 合计」。
4. 取 S：调用 erp_calc，参数 entity=ar_settlements、filter={"settle_date": {"lte": "当期月末"}}、group_by=customer_id、measures=[{"field": "settled_amount", "op": "sum"}]。记下每个客户桶的合计为 S_c，记下顶层 totals 给出的合计为「S 合计」。若该次调用返回 0 行（平账功能刚上线、尚无记录时就会这样，此时连 totals 也不会返回），则该项全部按 0 处理、「S 合计」记 0，不得因此重查或中断流程（第 2、3 步同样适用）。
5. 客户名映射：调用 erp_query，参数 entity=customers、fields=["id", "company_name"]（一次取回全部客户的 id→名称）；用第 2、3、4 步三个结果里出现过的全部 customer_id 到这层映射里取名，内部 id 不得作为名称报给用户。若该次查询返回 truncated: true（客户数超出单次上限），没取到名称的客户以「客户ID xx」占位并说明，不得编造名称。
6. 对齐（外连接）：第 2、3、4 步出现过的全部 customer_id 取并集为行集合；某客户在某一项无记录即记 0，某客户某项的结果为空串（""）也记 0（空串语义是「无有效样本」，不是数值，更不是负值）。
7. 逐户相减：当期应收_c = A_c − B_c − S_c，逐户一行；本流程只允许三类算术——①这一处「同一客户的三个数相减」，②第 8 步两项合计的求和（正数户相加、负值户相加），③第 8 步 (a)(b)(c) 三条校验所需的逐列求和；除此之外不得把多个客户的数值自行相加、也不得自行相减。
8. 合计与校验：A／B／S 三列的合计一律取第 2、3、4 步的 totals（某次调用返回 0 行时该项合计记 0，见第 4 步），不得把各户 A_c／B_c／S_c 自己相加；当期应收的合计 = 各户当期应收中**为正**的那些相加（负值户在**合计中**按 0 计、**不计入**），该数唯一正名为**实际应收合计（不含负值户）**；另求**负值户小计** = 各户当期应收中为负的那些相加（结果为负数）。四条校验：(a) Σ逐户 A_c = A 合计、(b) Σ逐户 B_c = B 合计、(c) Σ逐户 S_c = S 合计、(d) 实际应收合计（不含负值户）+ 负值户小计 = A 合计 − B 合计 − S 合计。任一条对不上就回去重查取数，不得带着对不上的数出报告。
9. 输出：表格逐户一行，列固定为 客户名、A 订单累计、B 累计实收、S 累计平账抹零、当期应收（= A − B − S）。A／B／S 三列必须并列列出供人工核对，不得省略；当期应收为负数的行照常列出该负数，不得改写成 0 或取绝对值，并注明该负数的含义（见 R4.balance.scope）。表格最后先是合计行（合计行之后若存在负值户则还有一行）：合计行的 A／B／S 三列填**全量合计**（取自 totals），其「当期应收」列填**实际应收合计（不含负值户）**并照此标注行名，不得写成「合计」了事——该行两处口径的差额（「A − B − S」减去该行「当期应收」列）即下一行；若存在负值户，紧接合计行之后是「未计入的负值户小计（N 户）」行，该行只在「当期应收」列填该负数、并在行名里写明户数 N，A／B／S 三列一律填「—」（仍占列、仍列出该行，不得省略）；若全部客户的当期应收都不为正（实际应收合计为 0 且存在负值户），须显式说明「当期无实际应收、全部为预收」，不得只给一个 0 了事；当期应收的算式与合计均取自上述取数与相减，不得另算或改写口径。
