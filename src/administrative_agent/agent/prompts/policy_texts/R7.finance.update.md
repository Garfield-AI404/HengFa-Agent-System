---
policy_key: R7.finance.update
title: 收支记录更新规则
version: 2026-09-29.1
---
1. 写前查询：更新前必须先用 erp_query 按 id 查询目标收支记录确认存在（写前查询），空结果不更新、不猜测（fail closed），须核对记录 ID 后重试。
2. 只改指定字段：只修改与当前值不同的字段（金额按数值比较，"165" 与 "165.00" 视为相同）；所有期望值与当前值一致时不调用 update（无需更新）；系统字段一律不改。
3. 分类一致性：category 变化时归属须按生效类型校验（目标类型 = 本次新填的 tx_type 或当前记录的 tx_type）——分类目录已由系统注入本轮上下文（或经 erp_query 查询 transaction_categories、按 tx_type 过滤取清单），category 必须从目录中选择；只改 tx_type 时现有分类必须归属新类型，否则一并修正分类，防止写出生理上不可能的「类型 × 分类」组合。
4. 金额与日期格式：amount 为金额（元，大于 0），两位小数规范化（方向由 tx_type 表达，恒为正，禁止负数/文字/公式）；tx_date 必须为 YYYY-MM-DD 且为真实日期。
5. 系统字段禁止：source_type/source_id/created_at/created_by/updated_at 等系统字段禁止传入（由 ERP 联动维护）；本地拦截 fail closed，一律不写入。
6. 版本一致性：执行时以最新快照重建确认卡与确认时内容比对（本地乐观锁）——记录内容已变化 → 确认失效，需重新查询并重新确认后执行，不覆盖他人新写入的数据；更新结果未知（网络/服务端）时先重新查询确认是否已应用，绝不盲目重复 update。
7. 确认卡：调用后系统自动展示确认卡（差异字段与预计影响），由用户点击卡片确认后执行，无需在文本中请求用户回复“确认”；执行失败或确认失效时不得自动重试同一写操作，须向用户说明原因并等待用户重新发起。
8. 同轮多条一次调用：同一轮要修改多条收支时，把所有明细放进 items 列表一次调用本工具（每条明细 = 目标记录 ID + 期望变化字段），系统只出一张确认卡，点一次确认即批量更新；一张卡最多 20 条，同一张卡内记录 ID 不得重复；禁止把同轮多条拆成多次调用。**超限（>20 条）例外**：不得自行删减条目、也不得只提交前 20 条；必须先向用户说明实际条数，并询问是否分批确认（分两张卡，例如先确认前 20 条、用户同意后再出余下）。
9. 部分失败与补写：批量更新时单条明细失败不中断其余条目；未完成项可再次发起同一工具补齐（已成功项自动跳过）。
