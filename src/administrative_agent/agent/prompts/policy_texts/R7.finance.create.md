---
policy_key: R7.finance.create
title: 收支记录创建规则
version: 2026-10-08.1
---
1. 分类强校验：分类目录已由系统注入本轮上下文（或经 erp_query 查询 transaction_categories、按 tx_type 过滤取清单），category 必须从目录中与所填 tx_type 同组的清单内选择且归属该 tx_type，禁止猜测或编造分类；注意区分「tx_type 的取值」与「category 的分类名」——tx_type 的取值只有 收入/支出/投资款 三个，它们本身不是分类名，而「投资款」既是一个类型词也是投资款组的唯一分类名，只有 tx_type=投资款 时才能选它；tx_type=支出 等其余情形选「投资款」会因归属校验失败被拒，未命中会报错并附可用分类清单，须按清单修正后重试。另：用户原话含具体用途名词（借支/垫付/押金/赔偿/罚款等）而目录中不存在语义对应的分类时，不得用「最接近」的分类顶替（如把「借支」填成「人情」「工资」）——在目录内挑一个语义对不上的，与编造目录外的分类同样禁止。应把该 tx_type 下的分类清单列给用户，请其指定后重试。本条优先于第 7 条「不反问」：第 7 条管的是查询能查到答案的参数，本条管的是只有用户才知道的意图。
2. 方向判定：用户口语开销语义（花了/付了/支付/买了/运费/房租/工资/水电/人情/售后等）→ tx_type=支出；收款语义（收到/收了/回款/打款/收款/进账/入账等）→ 收入；入股/投资 → 投资款。自查信号：所选分类组与用户开销/收款语义明显对不上 = 方向判错，应换组重选，禁止在错误组内硬凑分类；拿不准时按最常见开销语义就近判定（口语「花了 X 钱」几乎总是支出），确认卡会呈现方向供用户纠正，不得因方向没把握卡住不调工具。
3. 金额格式：amount 为金额（元，大于 0 的数字或数字字符串），按两位小数规范化（如 165 与 "165.00" 同值，存储为 "165.00"）；收支方向由 tx_type 表达，金额恒为正，禁止负数、文字或公式。
4. 日期格式：tx_date 必须为 YYYY-MM-DD 且为真实日期（如 2026-09-02），未指定时默认当天；不做其他猜测。
5. 外键存在性：填写 customer_id/supplier_id 前必须先用 erp_query 按 id 查询 customers/suppliers 确认记录存在；一条收支记录不同时填写客户与供货商（互斥），需确认后只保留一方。
6. 系统字段禁止：source_type/source_id/created_at/created_by 等系统字段禁止传入（由 ERP 联动维护）；本地拦截 fail closed，一律不写入。
7. 先查后答不反问：收支类型下的可用分类清单、客户/供货商 id、日期等可通过 erp_query 查到的参数一律先查再填，不反问用户能查到的问题。
8. 确认卡：调用后系统自动展示确认卡（含写入字段与预计影响，方向 tx_type 与分类组一并呈现），由用户点击卡片确认后执行，无需在文本中请求用户回复“确认”；执行前会再次复查分类归属（确认后分类表变化防御），复查未通过拒绝写入并说明。
9. 备注与项目口径：notes（备注）默认空值——仅当用户明确要求记录备注（如「备注：…」等明示）时才填写，用户未明示备注时不得填写，禁止把具体项目、用途或描述性内容塞进备注；project（项目名）**照用户原话填**——用户原话中陈述的具体业务内容（工程/订单/物料/产品/用途对象等，无论哪一类）照原样填入 project，不解释、不改写、不拣选、不自行归纳：如「买了不锈钢板，运费花了 165」→ project=不锈钢板；「XX 工程运费 500」→ project=XX 工程；原话只含开销与金额、没有任何业务内容时 project 留空。
10. 同轮多条一次调用：同一轮要记录多条收支时，把所有明细放进 items 列表一次调用本工具（每项自带 tx_type/category/amount/tx_date 等，每条明细 = 一条收支记录），系统只出一张确认卡，点一次确认即批量写入；一张卡最多 20 条；禁止把同轮多条拆成多次调用。**超限（>20 条）例外**：不得自行删减条目、也不得只提交前 20 条；必须先向用户说明实际条数，并询问是否分批确认（分两张卡，例如先确认前 20 条、用户同意后再出余下）。
11. 部分失败与补写：批量写入时单条明细失败不中断其余条目；未完成项可再次发起同一工具补齐（已成功项自动跳过），已写入的不重复写。
