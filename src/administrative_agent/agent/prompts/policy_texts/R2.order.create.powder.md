---
policy_key: R2.order.create.powder
title: 塑粉订单创建规则
version: 2026-09-29.1
---
1. 到货语义：塑粉是喷涂耗材粉末涂料，按色号从塑粉供货商采购；口语“XX 来了/到了/送来 YY kg 色号 Z 塑粉/粉”= 供货商送货到货 → 创建塑粉订单（供货商=XX、色号=Z、重量=YY kg、日期当天）；9010 等纯数字与 RAL 均为色号、不是钣金型号，不得把色号当钣金型号查金属订单或向用户询问钣金信息；客户与供货商同名（如同一“昌盛”同时是客户又是供货商）时按订单类型选对应实体（powder 查供货商），不反问用户是哪边。
2. 供货商匹配：订单必须指定供货商且与 ERP 供货商主数据唯一匹配；多个候选时询问确认。
3. 色号：塑粉订单必须提供色号（如 RAL 色号），色号缺失或不完整时询问补全，一般的色号是劳尔色号去除RAL后的纯数字搭配，比如9010这种。
4. 重量大于 0：塑粉订单重量必须大于 0，不允许 0 重量；用户未给重量或给 0 时询问确认（塑粉到货重量必填），不得填 0 占位。
5. 重量单位：固定 kg。
6. 供货商加色号历史价格：用户明确提供价格时以用户为准；未提供或填 0（0 仅表示待补充）时，按该供货商 + 该色号的口径查询往期订单中的价格后自动补全——唯一有效历史价自动补全，无历史价或存在多个不同价格时必须询问确认。
7. 总金额：total_amount 由 ERP 计算，禁止传入。
8. 创建日期默认当天；用户要求时可回溯到过往日期。
9. 同轮多条一次调用：同一轮要创建多个塑粉订单时，把所有明细放进 items 列表一次调用本工具（每条明细 = 一条订单），系统只出一张确认卡，点一次确认即批量写入；一张卡最多 20 条，且一张卡不得混装钣金与塑粉（order_type 恒在顶层）；禁止把同轮多条拆成多次调用。**超限（>20 条）例外**：不得自行删减条目、也不得只提交前 20 条；必须先向用户说明实际条数，并询问是否分批确认（分两张卡，例如先确认前 20 条、用户同意后再出余下）。
10. 部分失败与补写：批量写入时单条明细失败不中断其余条目；未完成项可再次发起同一工具补齐（已成功项自动跳过），已写入的不重复写。
