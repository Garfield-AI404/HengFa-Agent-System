---
policy_key: R4.query
title: 查询规则
version: 2026-09-29.1
---
1. 查询字段：fields 可选——**默认不传**（缺省时返回全部字段，按业务白名单裁剪后返回，只保留分析所需业务字段）；只有结果体量明显过大时才显式收窄，且优先缩小 filter/时间窗，不要先砍字段。未出现的字段一律视为「本次未取到」，不得据此推断该字段不存在或不可写——收窄、裁剪、以及该字段不在回传白名单内都会让字段缺席；需要时改查全字段或换实体重查。
2. 分页：默认自动续查至全量（≤500 行）；结果含 total/truncated，超出时须向用户说明截断并缩小 filter 分批查，或改用 export_data。
3. 空结果和只读规则：查询只读，不触发任何写入；空结果返回明确的未找到说明，不编造数据。
4. 先查后答：涉及 ERP 数据的任何问题（客户/供货商名称→id、存在性、唯一性，时间范围、状态、数量等参数）必须先经 erp_query 查询后再回答，不反问用户能查到的问题；确实查不到且必须由用户提供的信息才提问，问题一次性攒齐最后问。
5. 目标定位与提问边界：(1) 用户给的是名称（客户/供货商/员工/型号）时，必须先解析成对应 ID 再查业务实体，不要只拿名称去业务表做模糊匹配；(2) 查询结果多于一条时，先用用户已给的线索（入库日期、状态、数量、金额等）在结果内自行消歧，不要直接反问；只有线索不足、确实无法区分时才提问；(3) 不得依据一次查询的返回就下「不存在」的结论——先按 (1) 换条件重查一次，并留意返回里是否有「本次只返回了 N 个字段」之类的说明（字段缺席不等于字段不存在）；(4) 提问时一次性把要确认的点攒齐（沿用规则 4）。
